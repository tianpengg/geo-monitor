# 官网别名验收

日期：2026-10-29。变更 `add-site-aliases`；用于处理主域名与 Sitemap 中 www 地址不同、导致整份清单被拒绝的问题。

4 项任务已完成，三组正式规范同步后通过严格校验，归档于 `openspec/changes/archive/2026-10-29-add-site-aliases/`。

## 使用与升级

1. 更新控制台源码并重建，启动时自动迁移旧库，默认空别名；更新前按运维流程备份数据库和配置。
2. 在“官网配置 → 官网别名”填写同站域名，例如主域 `example.com` 对应 `www.example.com`，每行一个或用逗号分隔，最多 10 个，保存后生效。
3. 已启用的 Sitemap 在别名变化后自动重新排队；也可到“内容目录 → Sitemap 配置”点击立即同步。保存配置与同步成功分别展示。
4. 清空别名仅阻止该主机后续导入，不删除已有目录。主域、网站 / 来源标识和凭据保留，采集器无需重新安装。

Git 源码部署可先执行 `git pull --ff-only`，再在项目根目录执行 `bash scripts/deploy.sh`，复用既有配置及卷。最初通过 ZIP 部署的环境需下载新版源码更新程序文件，保留原 `deploy/.env` 和持久化卷；不要删除原部署目录或改成空配置。旧版本回滚需恢复配套旧库，不手工删除迁移字段。

## 实现边界

- 精确域名数组，标准化为小写 IDNA、去重 / 排序并排除主域，拒绝 IP、通配符、协议、端口、路径及超量输入。
- Sitemap 主文件、子文件、页面和本地 XML / CSV / JSON 共用允许清单；同路径合并到当前主域，不抓取页面正文，不增加日志来源。
- 每个实际下载主机使用自身 DNS / 固定公网 IP / TLS 校验；拒绝未登记域名、私网及跳转，原大小、数量和时限不放宽。
- 别名更新递增同步修订并失效运行 token，旧成功及旧失败都不能覆盖新配置，修改后又恢复原别名也不例外；启用配置重排，暂停保持，原目录与最后成功保留。
- 手动导入提交及同步配置核对当前站点和别名快照；同主域旧客户端省略字段保留原值，主域变化且省略字段时清空。
- 前端保存与载入检查会话代次，退出清空草稿，失败和后台刷新不覆盖输入；Sitemap 展示已保存允许域名。

浏览器实际检查：

- 未登记 www 时同步失败，新增别名保存后自动恢复；混合主域 / 别名的 3 条页面合并为 2 个路径，重载保留规范化别名。
- 非法别名返回 422，草稿保留；后台刷新不覆盖草稿。
- 保存请求未返回时，受控刷新返回 401；会话清除，迟到的成功响应不能恢复配置表单，忙碌时输入禁用；正常退出也移除表单。
- 320 px 时官网表单与 Sitemap 弹窗的 scrollWidth 均为 320，无横向溢出；允许域名、配置帮助和按钮可读。
- Tab 可从别名进入时区、从 Sitemap 地址进入同步选项。发现并修复既有 UiSelect 在下拉已关闭时吞掉 Escape 的局部缺陷；1440 / 320 px 均复验，关闭下拉时 Escape 关闭弹窗，展开下拉时第一次关闭列表、第二次关闭弹窗。

另以维护者给出的公开 Sitemap XML 只读检查：15 条页面通过登记别名后的解析，未写入数据库。本机环境的 DNS 代理使生产受限下载器看到非公网解析，因此其直接网络请求按预期被拒绝；XML 由普通只读诊断客户端取得后重放解析，不能据此声称部署服务器的 DNS / TLS 已复验。没有降低生产下载限制或自动登记实际域名。
