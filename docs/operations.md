## 官网配置怎么选

“官网别名”可填写同一官网实际使用的其他域名，例如主域名为 `example.com`、别名为 `www.example.com`。每行一个或用逗号分隔，最多 10 个，只填域名；不支持 IP、通配符、协议、端口或路径。保存后 Sitemap 和本地目录接受这些精确主机的页面，同路径合并到当前官网目录。别名不是第二个官网，不修改 Nginx、主域名、采集身份或混合日志的分站能力；未登记的 www / 子域仍会拒绝。

更新控制台后旧库自动增加空别名，原数据及凭据保留；旧客户端省略别名且主域不变时保留原值，主域变化且未提交别名时清空。显式清空仅停止接受该主机的新目录输入，已有目录不会删除。更新前按既有流程备份数据库，旧版本回滚需要配套旧库。

“统计时区”通过可搜索下拉选择，支持常用地区中文名称，也可搜索 `Asia/Shanghai`、`America/New_York` 等时区标识。中国大陆一般选“中国 · 北京 / 上海（北京时间）”。它决定“今天”、每日趋势的日期边界及后台访问时间显示，地区时区会按当地规则处理夏令时；不修改原日志时间。已有时区继续保留，即使不在当前浏览器目录中也会显示“当前配置”，不会静默切换。选择后点击“保存官网”才生效。

“日志中的 IP 是真实访问者吗？”指 Nginx Combined 日志第一列的地址，服务端用它对照可用的官方爬虫 IP 清单。经过 CDN 或反向代理时，这一列可能是代理服务器的地址。

- **还不确定（推荐）**：不清楚就选此项。日志采集和 UA 分类照常进行，来源核验显示“客户端 IP 不可确认”。
- **已确认是真实访问者 IP**：管理员已核对日志记录了真实访问者 IP，必要时已正确配置真实 IP 还原及可信代理。此时才使用该地址做官方来源核验，仍需命中有效官方清单才显示已核验。

这个选项不会自动修改 Nginx、CDN 或代理，也不保证核验通过。配置变更只作用于后续请求，历史核验不回算。仅改文案或打开页面不会更改已保存的确认状态。

## 一条命令部署（1Panel / Linux）

将完整项目源码上传到服务器，例如 `/opt/geo-monitor`，在具有 Docker 权限的终端运行：

```sh
cd /opt/geo-monitor
bash scripts/deploy.sh
```

首次按提示输入监测后台 HTTP 或 HTTPS 地址、主机端口和管理员密码（隐藏输入并确认，至少 12 个字符）；账号默认 admin，可用 `--admin-user` 指定。脚本检查 Docker / Compose，创建权限为 0600 的 `deploy/.env`，构建并启动控制台，健康检查通过后输出后台地址和本机上游。宿主机无需安装 Python 或 Node.js；配置校验也通过容器执行。

无需证书时填写 `http://服务器IP:8000`，或执行下列命令并将示例 IP 换为实际地址：

```sh
bash scripts/deploy.sh --public-url http://192.0.2.10:8000
```

HTTP 默认绑定 `0.0.0.0`，Cookie 不设置 Secure，监听端口默认跟随地址（未写端口时为 80）；在 1Panel 和云安全组放行该端口，即可直接访问，不需要证书或反向代理。HTTP 的管理员密码、会话、采集凭据和上报的原始日志未经传输加密，核验后业务库仍按原规则脱敏。脚本不会自动修改防火墙。地址表示浏览器与采集器实际访问的入口，端口转发或代理场景可用 `--port` 单独指定主机端口。

已有 `deploy/.env` 时直接复用，重复执行不更换密码、域名或数据卷。需要修改时编辑原配置，再运行同一命令；已有配置与 `--public-url`、`--port`、`--admin-user` 参数同时出现时明确拒绝覆盖。脚本不执行删除数据卷的操作；构建、配置或健康失败返回非零状态并保留配置。

选择 HTTPS 时，在 1Panel 为后台域名配置有效证书、启用 HTTPS 并反向代理至脚本输出的上游；主机默认仅监听 `http://127.0.0.1:8000`，Cookie 保留 Secure。此上游适用于 host 网络的 OpenResty，bridge 网络须配置共享 Docker 网络和可达上游。关闭后台代理缓存，请求体允许至少 2m。HTTP 使用已有代理时同样关闭缓存并允许至少 2m。容器就绪与公网访问、真实官网接入是分别验证的步骤。

后台可访问后，登录配置官网并生成采集凭据，复制页面安装命令；也可以在具有本项目源码的官网服务器执行（地址协议与实际后台一致）：

```sh
bash scripts/deploy.sh --collector http://192.0.2.10:8000 SITE_ID SOURCE_ID
# HTTPS 同样支持：将地址换为 https://monitor.example.com。
```

该模式转交安装脚本，继续隐藏输入采集凭据并预检日志路径，不自动改写 1Panel 网站配置。`SITE_ID`、`SOURCE_ID` 使用后台生成的实际标识。HTTP 安装自动在受限 `collector.json` 写入 `allow_http: true`；HTTPS 写入 false，下载和上报均验证证书，不允许 HTTPS 下载跳转降级到 HTTP。手工 HTTP 配置也须显式设置 `allow_http: true`。

无交互部署通过环境变量提供密码，避免写进命令行和 Shell 历史：

```sh
export GEO_PUBLIC_URL=http://192.0.2.10:8000
read -r -s -p '管理员密码：' GEO_ADMIN_PASSWORD; printf '\n'
export GEO_ADMIN_PASSWORD
bash scripts/deploy.sh --non-interactive
unset GEO_ADMIN_PASSWORD
```

可用 `--env-file /path/to/deploy.env` 指定受限配置位置，`--help` 查看选项。首次无交互部署缺少必要参数会失败；配置不会作为 Shell 代码执行，完整配置和密码不输出到终端。1Panel、Docker 和镜像仓库连接应事先准备，脚本不安装面板或 Docker。

## 控制台部署

前提：Linux 上已安装 Docker Engine 和 Compose，准备可达的 HTTP 地址或具有证书的 HTTPS 地址。官网本身无需迁入容器。除上述一键部署，也可首次在项目根目录手工执行：

```sh
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
# 编辑 deploy/.env，填写随机管理员密码（至少 12 位）和实际控制台地址。
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.yaml logs --tail=100 monitor
```

手工示例默认采用 HTTPS、仅绑定本机 8000 端口；参考 `deploy/nginx.example.conf` 配置反向代理和真实证书。HTTP 直连则将 `GEO_PUBLIC_URL` 改为实际 HTTP 地址，`GEO_COOKIE_SECURE=false`、`GEO_BIND_ADDRESS=0.0.0.0`，`GEO_PORT` 对应主机监听端口。后台地址必须与 GEO_PUBLIC_URL 一致。所有镜像依赖通过 uv.lock、package-lock.json 固定，前端在构建阶段编译，宿主机不需要 Python 或 Node.js。

切换既有部署的协议时，编辑同一配置文件中的地址、Cookie、绑定和端口后重跑，不删除卷。HTTPS 对应 Cookie true 和本机绑定，HTTP 对应 Cookie false；不匹配时脚本失败并保留配置。同步更新采集器后台地址和 `allow_http`，使用原来源与状态重连；重新运行安装命令也保留原状态卷。HTTP 的浏览器剪贴板 API 可能不可用，可手动选中复制页面显示的安装命令和凭据。

管理员密码由受限部署环境配置；修改后重启服务会更新登录密码并清除既有会话。完整采集凭据只在生成时显示，重新生成会使旧凭据失效；管理员密码和采集凭据不可互用。

## 采集器一次安装

1. 登录，填写单个官网的域名和时区，确认日志地址是否为真实客户端地址。没有确认时核验结果显示“客户端 IP 不可确认”。
2. 选择该官网独立的 Nginx Combined 日志，例如宝塔常见 `/www/wwwlogs/example.com.log`，实际位置以官网配置为准。标准 Combined 无 Host，不能用域名配置从混合文件分站。
3. 生成采集凭据，在官网服务器执行页面提供的安装命令。脚本从当前控制台下载固定文件白名单的采集器源码包，封装 Python 运行环境并本地构建镜像；不依赖尚未发布的镜像仓库。
4. 按提示输入日志绝对路径和采集凭据。凭据隐藏输入，通过受限配置文件交付，不放入命令行参数或安装日志。
5. 脚本检查 Docker、文件可读性、格式和连接；只读挂载日志目录，独立卷保存状态。预检通过才启动持续采集。

首次正式启用从当前 EOF 开始，不回灌安装前内容。初始文件为空时格式检查待验证；第一条完整日志仍按协议解析并报告异常。预检不会创建或覆盖采集状态。安装与上报支持 HTTP / HTTPS，协议由所填后台地址确定。

格式支持标准 Nginx Combined，以及 UA 后恰好多一个带引号字段的 OpenResty main（如 1Panel 常见的转发地址列）。预检和持续解析使用相同规则；附加字段被忽略，不作为真实客户端 IP，不进入事件或采集状态。多个附加字段、未加引号尾部或损坏行仍拒绝。不要为了接入改变主站日志格式；IP 不确定时保持后台“不确定”。通用部署与接入分步指引见 [1Panel 部署操作](1panel-deployment.md)。

默认安装目录为 `$HOME/.local/share/geo-monitor-collector`，可用 GEO_INSTALL_ROOT 指定。文件 `collector.json` 包含凭据，`collector-env.sh` 仅包含日志目录；安装脚本以受限权限创建它们。采集器不监听入站端口。默认容器以 root 读取既有日志；可以通过 GEO_COLLECTOR_UID/GID 指定已有日志读取用户，同时确保状态卷可写、配置可读。

只需要准备独立日志的绝对路径和采集凭据，后台地址及网站 / 来源标识已在页面命令中。日志不可读时先核对只读挂载、已有用户和目录权限，不要使用 `chmod 777`。后台的“日志中的客户端地址”指 Combined 第一列：若它是 CDN / 代理地址或无法判断，选择“不确定”，不影响采集和 UA 识别。

## 采集器运行边界与资源配置

采集器只读源文件，不修改 Nginx 或官网，不参与请求响应；停止采集器不会主动停止官网。它仍会占用同机 CPU、内存、磁盘和网络，不能承诺零影响。建议控制台独立部署，官网低峰安装：首次安装的源码镜像构建开销不受下面的运行限额约束，资源紧张时先在其他机器准备兼容镜像。

当前 Compose 默认配置 0.25 CPU、128 MiB 内存、64 PID，根文件系统只读，仅状态卷及 16 MiB `/tmp` 可写；Docker 输出日志每文件 5 MiB、最多 2 个。保持源日志及配置只读，不开放采集器端口、host 网络、特权模式或 Docker socket。配置已经 Compose CLI 校验，真实限额、只读运行与 OOM 恢复仍待 Linux Docker 验收，详见 [本轮检查报告](completeness-audit.md)。

需要调整 CPU / 内存时，在执行安装或重连的同一个 shell 提供覆盖值，例如：

```sh
root="$HOME/.local/share/geo-monitor-collector"
GEO_COLLECTOR_CPUS=0.5 GEO_COLLECTOR_MEMORY_LIMIT=256m \
  bash "$root/scripts/collector-control.sh" "$root" reconnect
```

这两个覆盖值不会由安装器自动保存，后续重建须再次提供相同值；可以由管理员维护在自己的受限部署环境中。不要为调整限额删除状态卷。

`collector.json` 可增加 `catchup_pause_seconds`，默认为 0.25 秒，允许 0.05–30 秒：有积压时每批等待，正常空闲仍采用 `flush_seconds`（默认 10 秒），失败保持退避，心跳独立。每轮新增源数据最多读取 256 KiB，不包含元数据及文件身份锚点读取；异常长行分轮扫描、行尾完整后只计一次诊断，重启可能重扫未确认部分。相同状态不反复落盘。这些措施降低读取和状态写放大，不是磁盘 IO 硬限额；调整后仍须按真实日志量核对补采速度与保留窗口。

## 更新爬虫识别规则

登录后进入“爬虫规则”，可直接新增、编辑或启停身份。填写固定标识、UA 匹配词、显示名称、运营方及产品归属说明；有官方 IP 清单时再填写 HTTPS 核验来源与解析格式，保存后点击该条“刷新核验”查看结果。没有证据时保留 UA 匹配，不必为了启用规则填写猜测的地址。详细字段、历史语义与来源限制见 [识别规则说明](crawlers.md#后台维护规则)。

规则保存在控制台数据库，保存后用于下一批新增请求，无需重新部署控制台或更新采集器。旧记录保留原分类、版本及核验结果；停用规则仍可筛选历史。多窗口修改出现冲突时重新点击“编辑”载入当前配置。升级先备份数据库；新规则表由迁移创建，原站点与读取位置不变，旧程序回退需配合升级前数据库备份。

## 停止、预检和重连

```sh
root="$HOME/.local/share/geo-monitor-collector"
bash "$root/scripts/collector-control.sh" "$root" stop
bash "$root/scripts/collector-control.sh" "$root" check
bash "$root/scripts/collector-control.sh" "$root" reconnect
```

停止与重建容器不删除状态卷。源文件仍保留时，重连从已确认位置补采；不要为解决连接错误而删除状态。后台凭据被重置后重新运行安装命令输入新凭据，原来源标识及状态卷仍保留。

也可在受限编辑器内更新安装目录 `collector.json` 的 `token`，保留原网站、来源及日志配置，再执行上面的 `check` 和 `reconnect`。单独重连不会自动更新凭据。保留配置文件权限，不在终端输出完整凭据；不要执行 `docker compose down -v`。

同一来源只运行一个采集进程，运行时会锁定状态文件。采集器保存字节位置、内容摘要、确认和缺口元数据，不新增含原始 IP 的离线日志副本。断网期间来源日志是补采依据。

## 轮转和保留窗口

- 支持同目录（或 rotation_pattern 明确指定的目录内）重命名旧日志并创建新日志，重启后按文件身份恢复。
- 默认查找指定文件名的轮转后缀，不自动采集其他网站日志；安装前已有的轮转文件不会作为新增访问回灌。
- 恢复前提是原始格式文件仍保留。提前压缩、移出允许目录或清理未确认文件后可能无法补采，后台显示已知缺口，无法确认的数量显示未知。
- 推荐采用 Nginx 重命名加重新打开方式，并保留足够的未压缩文件。copytruncate 有固有丢失窗口，检测到时展示完整性限制；无法承诺检测所有竞态或绝对零丢失。
- 源日志保留和轮转由官网维护，本项目不更改 Nginx、不删除或改写官网日志。

## 状态与排障

默认 10 秒批量上报、30 秒心跳、90 秒心跳超时；后台每 30 秒刷新。无流量仍有心跳；普通访问没有匹配爬虫也推进接收和处理时间。

| 状态 | 操作 |
|---|---|
| 待安装 | 检查预检结果、网站和来源标识 |
| 断连 | 查看最后心跳，检查容器、网络、HTTP(S) 地址及相应协议配置 |
| authentication | 核对凭据是否重置、来源是否正确，更新配置后重连 |
| protocol | 检查采集器和服务端版本、位置确认及批次错误，不删除状态规避 |
| unreadable / missing | 检查容器内日志目录挂载、路径和权限 |
| 正在补采 | 保留源日志并等待确认，不将积压认定为永久丢失 |
| 已知缺口 | 结合日志保留与轮转定位原因，未知数量不能推断为零 |

核验证据获取失败不阻塞正常采集。系统区分 UA 匹配、已核验、不匹配、证据不可用及客户端地址不可确认；来源核验状态不代表内容被训练、引用或转化。

## 备份与恢复

页面分析和目录增强使用追加式数据库 schema 2。升级前执行下述一致备份，使用相同 Compose 配置重新构建并启动；启动事务迁移会保留原访问、来源及读取状态。旧版本拒绝较新 schema，回退须使用兼容程序或恢复升级前备份，并评估升级后的新增数据；不能删除目录表冒充无损降级。

SQLite 含官方 WAL-reset 修复时启用 WAL，未确认修复的旧引擎采用 DELETE 模式；两者使用相同事务和 backup API。依据：[SQLite 官方说明](https://sqlite.org/wal.html#walreset)。

服务端使用 SQLite backup API 创建一致备份：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml exec monitor \
  python -m internal.storage backup --database /app/data/monitor.sqlite3 --output /app/data/backup.sqlite3
```

将生成的备份、受限部署配置和采集器配置保存到管理员的备份位置。采集器状态备份先停止采集器，再从 collector-state 卷复制 state.json；恢复前保持原来源标识。不要只复制正在写入的 SQLite 主文件而忽略 WAL。

恢复服务端时停止容器，将一致备份放回数据卷中，并使用与数据库版本兼容的镜像启动；服务端拒绝更高版本数据库。恢复采集器状态后补采保留的原始日志。主动重置状态会建立新基线并改变覆盖范围，不能当作无损恢复。

## Sitemap 自动维护

在“内容目录”点击“Sitemap 配置”，在弹窗填写当前官网的 Sitemap 完整地址，支持标准端口 HTTP / HTTPS。保存成功后弹窗关闭；启用后后台立即排队，以后每 24 小时尝试一次。可再次打开弹窗暂停自动同步或点击“立即同步”，主页面保留同步摘要和失败提示。配置与结果保存到数据库，重启后继续，到期检查周期最多 30 秒。中断任务的 5 分钟租约过期后恢复。保存只表示已配置，结果以同步状态、最近成功和下次时间为准。

本地文件通过“手动导入”弹窗选择，合并导入成功后关闭并刷新目录；校验或接口失败时保留文件并在弹窗提示，可重新选择后提交。取消、关闭或 Escape 不保存未提交内容，重新打开恢复已保存 Sitemap 或空文件选择。读取与提交期间禁止重复操作或关闭；表单使用既有自定义控件，手机弹窗内部滚动，底部操作保持可达。

支持 UTF-8 urlset、单层 sitemapindex 和 gzip；主文件、子文件和页面地址须属于当前官网主域名或“官网配置”中已保存的精确别名。同路径按当前官网合并；例如在 `example.com` 配置中登记 `www.example.com` 后，两者的 `/products` 只算一个目录页面。每个下载主机独立执行公网 DNS、固定 IP 连接及原主机证书校验。最多 20 个文件（包含索引），单文件下载及解压后各 1 MiB，累计解压 10 MiB，输入和目录最多 10000 页。HTTP 跳转、未登记主机、私网地址、证书错误、XML DTD / 实体、空或无效清单及超限均拒绝；请填写可直接返回 XML 的最终地址，不填需要登录的网页。协议格式依据 [Sitemaps 官方协议](https://www.sitemaps.org/protocol.html)。

保存别名变化会使旧任务失效，已启用的 Sitemap 自动重新排队，已暂停的仍保持暂停；最后成功信息和目录保留。删除正在使用的别名后，后续同步会提示地址不在允许范围，需要改用主域地址或重新登记；不自动跟随跳转、改写 Sitemap 地址或删除历史目录。

每次完整校验后合并路径、保留手动标题和旧页面，不自动删除 Sitemap 已移除的页面，不下载页面正文。失败保留目录及上次成功结果，仍按周期重试。手动移除的页面如果仍在 Sitemap 中，下次同步会重新加入；暂停不会删除目录。官方证据源继续要求 HTTPS，Sitemap 的 HTTP 支持不改变证据核验限制。

同步配置按官网主机隔离，改域名后需重新配置；旧任务不写入新主机目录。新增数据库表前先按既有步骤备份 SQLite；回退使用对应版本及备份。
