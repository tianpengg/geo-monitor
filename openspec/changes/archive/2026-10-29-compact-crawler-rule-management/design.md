# Design

## Context

见 proposal.md。现有 RulesView 将列表和编辑器同时渲染，useCrawlerRules 保留草稿和修订；共用 UiPopup 将下拉传送到 body，不能直接换成使外部下拉失效的原生模态对话框。

## Goals / Non-Goals

Goals：主页面用于浏览紧凑表格，按需打开可访问的编辑器；保留原接口与冲突处理。Non-Goals：新增规则字段、批量操作、排序或后端行为变更。

## Decisions

- 单个卡片包含搜索、计数、新增和刷新；六列表格合并显示名称与标识、运营方与归属、UA 与版本、核验、状态、操作。窄屏仅表格容器横向滚动。
- 新增 UiDialog 共用组件：body 传送、模态语义、背景 inert、滚动锁、焦点循环与恢复，支持关闭 / 取消 / Escape；下拉沿用 UiPopup，层级在模态之上，Escape 先关闭下拉。忙碌时拒绝关闭，卸载与会话清理恢复背景状态。
- useCrawlerRules 管理弹窗开关；打开时初始化相应草稿，取消及保存成功清理，错误继续使用现有失败处理并在弹窗内呈现、聚焦。成功返回表格，列表刷新不丢失搜索。

## Risks / Trade-offs

- 模态与传送下拉的焦点冲突 → 允许当前下拉内交互并验证 Escape / Tab，背景仍 inert。
- 手机长表格 / 长表单 → 表格内滚动、弹窗内容滚动、固定操作区，测试 320 px。
- 本地预览已供用户查看 → 构建后刷新同一标签页，保持现有隔离数据库，不操作 Docker 或真实官网。
