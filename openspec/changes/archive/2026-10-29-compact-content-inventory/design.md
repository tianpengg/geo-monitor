# Design

## Context

见 proposal.md。InventoryPanel 当前包含上传和统计两张卡，SitemapPanel 包含独立配置卡；UiDialog 已有背景隔离、键盘和忙碌保护，规则页已复用。工作区已有接口及过时查询防护，保存 Sitemap 的返回类型仍为 void，上传异步读取目前没有卸载保护。

## Goals / Non-Goals

Goals：收起低频表单，统计和表格靠前；弹窗结果与真实接口一致，错误及取消行为完整。

Non-Goals：不改变服务端、数据库、同步策略、统计、目录合并和页面移除逻辑，不重新设计全站或引入组件库。

## Decisions

- InventoryView 管理互斥的 Sitemap / 导入弹窗入口及紧凑状态摘要；InventoryPanel 只保留统计、列表和筛选。复用现有页面外壳与分析样式，不重复增加页头。
- SitemapPanel 改为 UiDialog 配置弹窗，新增 InventoryImportDialog 分离文件选择与说明。两个组件保持挂载，以便通用弹窗完成关闭后的焦点恢复；打开时初始化草稿，取消清理；已有持久化结果只读展示。
- 工作区的保存与导入返回 boolean 成功结果，调用方据此关闭；保留原有成功消息，补齐上传的会话代次与主机检查。文件读取辅助函数放 utils/inventoryImport.ts，校验格式、大小与 UTF-8，组件用读取忙碌和卸载代次阻止迟到提交。
- 错误在弹窗内展示并聚焦，主页面也保留 Sitemap 下载失败摘要。保存成功只表示配置完成及任务排队，远程同步失败按已有服务端状态呈现，不使弹窗无限等待任务。

## Risks / Trade-offs

- 弹窗收起后可能忽略同步失败 → 主页面保留状态和错误摘要及配置入口。
- 文件读取晚于关闭或卸载 → 读取期间禁用关闭，卸载时失效代次；API 成功后确认会话及官网后再更新。
- 全站轮询影响草稿 → 打开时初始化，轮询不改写未保存输入；弹窗内容自身滚动，复用固定页脚操作。
