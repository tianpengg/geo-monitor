# Design

## Context

现有 Vue 单文件已提供完整登录、配置、安装、筛选和健康查询。服务端 overview 同时返回真实统计、核验分布、覆盖状态与健康快照，不需要新增接口。视觉真值为 `web/prototypes/overview-motion/` 中用户确认的无人物版本。

## Goals / Non-Goals

将参考布局落到正式应用，保留已交付功能、隐私和认证边界。生产界面不包含预览数据、固定时间、状态模拟器或动画人物；不新增框架和生产依赖。

## Decisions

- 继续使用 Vue 3、TypeScript 和 Vite；应用保留简单页签导航。拆出图标、趋势、健康和访问表格组件，类型与格式转换集中管理，避免在模板中重复推导状态。
- 复用本地 Tabler SVG 与 Inter，随构建提供许可证。图表用可访问的 SVG 数据图形，未观测点断线且显示覆盖标记，不填零；部分观测明确标注。单日只有一个实际自然日点，不伪造小时趋势。
- 识别量、已核验量、页面和活跃爬虫直接来自 API；排行使用服务端身份名称，近期记录独立于明细的爬虫筛选及分页。
- 表单草稿与已应用筛选分开，校验通过后提交；新筛选重置游标，自动刷新保留筛选和页码。请求使用序号防止过时响应覆盖新状态，401 清理会话及私密状态。
- 更新失败保留最后成功数据并标记过期，不将失败展示成正常零值。健康卡完全依据服务端状态，未返回的时间与数量显示暂无或未知。
- 使用 Node 24 原生 TypeScript 测试执行器验证格式、健康映射和趋势断点，不引入测试依赖；真实 FastAPI 临时数据库浏览器检查覆盖管理流程与状态。

## Risks / Trade-offs

- 生产真实数据可能含长路径或多种核验状态：桌面表格允许局部滚动，手机改为记录卡，保留完整字段与依据。
- 服务端可能失败或响应顺序变化：明确加载、过期与失败状态，并验证旧响应不会覆盖新查询。
- 原型为全覆盖样本，生产可能有未观测时段：保留原图表视觉但优先表达覆盖限制。

## Validation

前端单元测试、类型与构建、现有 Python 回归；独立浏览器验证登录、配置和凭据、概览、组合筛选与分页、各健康状态、自动刷新、失败与过期会话、桌面和手机布局。截图及浏览器输出保存在忽略的 output 目录。
