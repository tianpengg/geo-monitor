# Design

## Context

见 proposal.md。已读取现场 main 样本，使用文档保留 IP 的合成样本复现拒绝；COMBINED 同时服务于预检与 parse_line，后者固定解包六组。

## Goals / Non-Goals

Goals：无需改动官网，兼容一个明确后缀；用真实回环服务及采集进程验证新增、重启和不重复计数。

Non-Goals：不支持任意自定义日志、不自动信任 X-Forwarded-For、不导入历史、不登录后台或在真实服务器执行安装。

## Decisions

- 在已有表达式后加入非捕获、最多一次的带引号后缀，保留现有六个捕获组与转义规则。避免任意尾部通配和逐段 split，防止带空格的请求 / UA 被错切。
- 不新增字段或配置，附加值不出解析器；第一列 IP、IP 信任模式、偏移和 MAX_LINE_BYTES 继续沿用。缺失后缀时完全兼容旧格式。
- 发布源码包使用当前生产构建入口，排除 .git、环境、缓存、运行数据、真实配置和 node_modules；验证包目录与内容摘要。1Panel 指引用已确认的宿主机路径和独立 HTTP 后台示例，保留可选 HTTPS 与实际待验边界。

## Risks / Trade-offs

- 名为 main 的自定义格式仍可能不同 → 仅支持所定义结构，其他格式继续拒绝。
- 把附加地址误认为可信 IP → 丢弃该值，说明保持不确定模式，须另行确认代理配置。
- 同机镜像构建消耗磁盘和 CPU → 指明现场剩余约 4.7 GB 是瞬时值，先核对资源，不清理既有容器 / 镜像或修改主站。

## Migration Plan

重建控制台使下载源码包带上解析修复，再安装 / 更新采集器；复用原状态卷和来源标识。没有数据库迁移。真实容器 / 官网验收继续作为现有活动变更的待验事项。
