# Design

## Context

目前官网 API 仅保存主域名；本地导入与远程 Sitemap 共用 normalize_page，严格比较主机名。受限下载将站点主机用于 DNS 和 TLS；调度已通过配置修订与运行 token 防止旧结果提交。Vue 复用官网表单和 UiInput，不增加组件体系或依赖。

## Goals / Non-Goals

**Goals:** 为管理员明确登记的同站域名提供统一允许范围，保留单站目录分母、只读采集和受限获取，覆盖旧库升级及配置并发。

**Non-Goals:** 不自动探测域名所有权、跟随跳转、推定根域全部子域可信；不修改 DNS / Nginx、采集器和历史统计，不引入多站、多来源或公网生产操作。

## Decisions

- site 表新增 aliases TEXT NOT NULL DEFAULT '[]'，存规范化 JSON 数组，最多 10 项；沿用现有域名校验再拒绝 IP。API aliases 省略时，同主域更新保留旧值，主域变化清空；显式列表去重、排序并排除主域，避免无意义顺序变化触发同步。采用原表一列而非独立多站表，以保持当前边界。
- normalize_page、parse_inventory、sitemap_url 和 collect_pages 接受别名快照，未提供时行为与旧版一致。下载前用允许集合校验 URL，但传给实际下载器的是 URL 的主机；下载器仍自行检查公网 IP、固定连接和 TLS。不会用主域的 DNS / 证书替别名担保，不在页面地址上发请求。
- 别名或主域变化与该官网已保存 sitemap_sources 修订递增、运行 token 失效在同一事务内完成；启用者排队，暂停者保持暂停，调度仍只领取当前主域配置，最后成功信息和目录保留。任务领取时读取当前别名，旧成功与旧失败均受修订 / token 控制；一次同步完成也不能覆盖中途改动。配置和手动导入提交时核对站点 / 别名快照，拒绝过时请求。
- 官网表单增加多行别名文本，空值提交 []；后台回填数组为换行。复用工作区，保存和加载检查会话代次，退出清理草稿；自动数据刷新不回填编辑字段。Sitemap 弹窗显示主域及已保存别名，未登记地址错误提示引导官网配置。使用示例域名完成隔离验收。

## Risks / Trade-offs

- 管理员误登记外站 → 明确同站确认说明，精确匹配、数量限制、无自动通配；下载仍执行网络隔离。
- 删除正在使用的文件别名 → 旧任务失效，新任务明确报域名错误，保留旧清单和最后成功；不会自动改写地址或删除目录。
- 旧版本不能读新版 schema → 更新前按既有运维备份，回滚需恢复配套旧库，不手工删除字段。
- 源日志没有主机字段 → 别名只作用于目录地址允许范围，不宣称可从混合多站日志拆分请求。

## Migration Plan

服务端启动时执行现有事务迁移，旧站默认空别名且原身份和数据不变。更新控制台代码并重建镜像后，在官网配置保存需要的别名；已有启用 Sitemap 自动重新排队，也可点击立即同步。采集器无需更新或重装。只运行隔离数据库、受控下载和浏览器测试，不访问生产控制台或写入官网。
