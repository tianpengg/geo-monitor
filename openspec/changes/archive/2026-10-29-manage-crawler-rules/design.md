# Design

## Context

见 proposal.md。当前 `Rule` / `RULES` 为静态身份与解析依据，接收按 token 保存事件，证据以 token 缓存；已有事件保存名称与规则版本。统计按 crawler/name 分组，改名会拆分同一身份的排行，需改为稳定身份聚合。数据库当前有两次迁移，Vue 按 workspace 中的 tab 组装页面。

## Goals / Non-Goals

Goals：管理员维护完整规则与证据来源；即时分类、重启持久化和历史一致；复用现有认证、CSRF、控件与测试基础。

Non-Goals：任意正则、历史重算、批量规则导入、模型能力探测、删除历史身份、自动认可未经确认的平台归属。停用代替删除，最多 256 条。

## Decisions

- 增加 `crawler_rules` 迁移，启动时事务性初始化现有 20 条，仅在空表首次初始化。标识沿用 token 并不可变，单独的 UA 匹配词可编辑；当前字段、来源、启用、修订和时间持久化。修改需携带预期修订，冲突返回 409。
- 每批接收读取同一启用规则快照，按匹配词长度降序、标识排序选择完整词；有界缓存编译模式，不缓存数据库当前配置。事件保存所用版本；排行和页面分析按稳定 crawler 聚合，历史详情仍保留当时名称。内置种子初始版本保持旧常量兼容，后续修订带版本号。
- 证据维护读取数据库启用规则；更换 UA、证据源、格式或启停时清除该规则缓存，仅名称等元数据修改保留可用证据。保存和失败处理校验当前版本及来源，防止进行中的旧刷新覆盖。手动刷新只处理单条，保存不阻塞于网络。
- 自定义证据必须 HTTPS 默认端口、无凭据，服务端解析全部地址并拒绝非公网 IP；连接固定到检查过的地址，TLS 仍验证原主机，禁止重定向，5 秒连接/读取和 1 MiB 响应上限。沿用 JSON 与 Amazon 代码块解析，不增加依赖。测试使用显式注入客户端，生产不使用不安全开关。
- 规则页复用 workspace 认证状态、UiInput / UiSelect 和既有卡片布局；独立 composable 负责规则列表与草稿，请求序号与退出清理防止迟到恢复。官网未配置也允许进入规则页。停用规则继续出现在历史筛选选项中。
- 保留 Bytespider、HySpider 的已确认展示与归属边界；自定义核验源是管理员声明的官方依据，文档明确其真实性由管理员确认，IP 清单匹配不是模型训练或引用证明。

## Risks / Trade-offs

- 配错 UA 或证据导致误识别 → 完整词、唯一性、版本、来源状态和清晰说明；无证据不自动核验。
- 自定义 URL 带来服务器侧请求风险 → 公网解析检查并固定目标连接，证书验证、禁止跳转及响应限额，相关网络边界单测。
- Docker 仍不可用 → 本变更以 SQLite / API、前端构建和隔离浏览器验证其行为；容器重部署矩阵保留在原 HTTP 活动变更，不混称已通过。

## Migration Plan

升级自动创建规则表并初始化种子，不更改历史事件和采集器状态。备份包含规则配置。数据库版本升级后旧程序不能直接使用新库；回退应使用升级前备份。规则迭代通过后台完成，后续程序升级不覆盖已维护规则。
