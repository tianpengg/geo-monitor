# Proposal

## Why

现有爬虫身份、UA 和核验来源写死在代码中，平台更新或新增身份时必须重新开发部署。管理员需要直接在后台维护规则，并明确规则变更与历史记录、来源核验的关系。

## What Changes

- 将现有 20 个身份作为 SQLite 初始规则，提供管理员新增、编辑、启停与单条证据刷新。
- 可维护 UA 完整词、名称、运营方、归属说明、官方资料及 HTTPS 核验地址与格式；稳定标识保留，修改版本可追溯。
- 保存后对下一批新增请求生效，不重写历史、不回灌未知请求，不需要更换采集器。
- 更换证据源后旧证据失效，禁止后台抓取内网、无效证书或跳转的自定义来源。
- 增加与现有浅色界面一致的爬虫规则页，复用自定义表单，保留历史筛选与退出防护。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `crawler-identification`: 持久化动态规则、启停、版本、有效证据及历史一致性。
- `admin-dashboard-interface`: 规则管理、验证、冲突提示与即时使用说明。

## Impact

涉及 crawler、storage 迁移、服务端管理 API 与接收、证据维护、Vue 导航及表单、回归及说明。无需新生产依赖，不改变日志采集协议、单站边界或 IP 脱敏。HTTP 部署变更继续独立保留待验收；不恢复或重试用户已暂缓的 Docker 环境。
