# Proposal

## Why

官网管理员需要持续了解可识别的 AI 爬虫是否访问过网站，同时判断数据是否正常采集、来源是否经过核验。首版通过一次安装的只读日志采集器和自托管后台，建立可验证、可追溯的访问记录。

## What Changes

- 建立单管理员登录及单官网配置，生成网站标识和独立采集凭据。
- 提供 Linux / 宝塔 + Docker 采集器安装入口，检查指定站点的 Nginx Combined 日志格式、读取权限和连接状态。
- 从首次启用后的新增日志开始，批量上报并保存读取状态，处理断网重试、重启续传、轮转和重复上报。
- 校验凭据、识别爬虫并使用可用的官方证据核验来源；原始 IP 核验后脱敏保存。
- 按分钟更新今天、近 7 天、近 30 天的概览，提供按日期和爬虫筛选的访问明细。
- 独立展示心跳、接收与处理时间、积压、采集异常和已知缺口，区分没有匹配记录与无法正常观测。
- 国内平台按明确口径展示，不将 Bytespider、HySpider 直接归属为豆包或元宝；千问、DeepSeek 规则未确认时展示识别能力待完善。
- 提供自托管部署、安装、停止、重连和数据持久化说明，并建立与这些能力一致的代码目录骨架。

范围为一个管理员、一个官网、一条独立日志来源。品牌引用、内容评分、GEO 权重、转化分析、爬虫访问控制、通知告警和 CDN 接入不在本次变更内。源站日志不代表全部边缘流量。

## Capabilities

### New Capabilities

- `admin-site-configuration`：管理员登录、单官网配置、网站标识与采集凭据。
- `collector-installation`：采集器安装配置、日志与连接预检及首次启用。
- `incremental-log-collection`：增量读取、确认位置、重试、幂等上报、轮转与缺口记录。
- `crawler-identification`：凭据校验、UA 分类、官方来源核验、国内展示口径及隐私处理。
- `traffic-overview`：指定时间范围的请求量、不同路径数、最近访问时间与趋势。
- `traffic-details`：访问明细、日期和爬虫筛选及核验信息。
- `collector-health`：独立心跳、采集与处理状态、积压及观测覆盖情况。
- `self-hosted-deployment`：Docker 部署、持久化、停止与重连操作及首版验收。

### Modified Capabilities

无。项目尚无正式能力规范或业务实现，本变更定义首版待实现能力。

## Impact

- Python 代码采用 `src/geo_monitor/` 包布局，`server/` 提供 FastAPI 服务，`collector/` 提供独立采集进程；`logparse/`、`crawler/` 和 `storage/` 分别负责解析、核验和存储。
- `web/src/` 承载管理后台；`deploy/`、`scripts/`、`tests/` 分别承载部署、运维和验收。
- 计划引入 Python + FastAPI、Vue 3 + TypeScript + Vite 和 SQLite；新增管理员会话、官网配置、批量接收、心跳、概览及明细接口。
- 当前按实施任务交付上述业务能力；界面视觉设计由用户后续补充，本次先交付可验证的功能页面、交互及 API。
- 容量验证按用户确认的合成测试基线执行并明确适用边界；真实官网峰值、平均行大小、轮转及未压缩保留窗口在生产部署前补充并复验。
