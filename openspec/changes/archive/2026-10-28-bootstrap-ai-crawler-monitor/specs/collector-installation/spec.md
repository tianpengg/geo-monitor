# Spec Delta

## Purpose

帮助管理员在官网服务器完成一次可检查的采集器安装，明确连接目标、凭据和日志路径。通过区分预检与正式启用，确认读取条件和来源范围，并让首次采集起点及后续重连行为可观察、可复现。

## ADDED Requirements

### Requirement: 安装入口和配置

系统 SHALL 提供面向 Linux / 宝塔 + Docker 的安装命令及简短说明，要求配置后台地址、网站标识、采集凭据和一条日志路径，并说明只读日志挂载及状态持久化。

#### Scenario: 使用安装说明
- **WHEN** 管理员在官网服务器按说明填写配置并安装采集器
- **THEN** 采集器能够运行预检，安装过程不改写官网日志或自动修改 Nginx 配置

### Requirement: 日志和连接预检

采集器 SHALL 检查路径存在性、读取权限、Combined 格式兼容性、后台连接和凭据有效性，逐项报告结果；预检不得消费待采集数据或覆盖已有确认位置。

#### Scenario: 检查通过
- **WHEN** 指定日志可读、样本符合格式且后台接受凭据
- **THEN** 安装界面报告通过并允许正式启用采集

#### Scenario: 权限或格式不符合
- **WHEN** 路径不可读或日志样本不符合支持格式
- **THEN** 采集器报告具体失败项及修正方向，不报告安装成功

#### Scenario: 空日志文件
- **WHEN** 日志文件存在且可读但没有可供检查的完整行
- **THEN** 系统将格式检查标记为待验证，在收到首条完整日志时完成检查，不将空文件等同于格式错误

#### Scenario: 网络或凭据错误
- **WHEN** 后台不可达或拒绝采集凭据
- **THEN** 采集器区分连接失败与认证失败，保留已有读取状态

### Requirement: 单站独立日志来源

安装说明 SHALL 要求使用该官网独立的访问日志，明确标准 Combined 不包含 Host 字段；一条来源的轮转文件属于同一来源，不得自动纳入其他网站日志。

#### Scenario: 选择混合访问日志
- **WHEN** 管理员查看日志来源要求或声明所选文件包含多个官网
- **THEN** 系统说明域名配置不能从该格式中可靠分站，并要求改用该官网独立日志

### Requirement: 首次正式启用基线

采集器 SHALL 在首次正式启用时持久化采集起点，仅处理该起点之后的新增日志；已有状态的重启或重连不得重新建立末尾起点。

#### Scenario: 文件中已有历史数据
- **WHEN** 首次启用时访问日志包含历史内容
- **THEN** 系统记录当前末尾作为基线，不将历史内容上报为安装后的访问

#### Scenario: 重连时已有未确认内容
- **WHEN** 采集器使用原状态重新连接且源文件仍有未确认内容
- **THEN** 系统恢复原确认位置并补采，不跳到当前文件末尾
