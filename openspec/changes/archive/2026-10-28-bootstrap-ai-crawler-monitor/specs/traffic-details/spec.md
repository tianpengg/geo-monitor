# Spec Delta

## Purpose

为管理员提供与概览同一口径的逐条爬虫访问记录，使其能够按日期和爬虫定位具体页面访问，并理解每条记录的声明身份与核验结果。通过稳定分页和隐私约束，保证补采、重复上报及筛选情况下的查询结果仍可解释。

## ADDED Requirements

### Requirement: 明细字段和展示口径

系统 SHALL 展示访问发生时间、页面路径、请求方法、状态码、爬虫名称和来源核验状态；页面路径不包含查询参数，时间与概览使用相同官网时区。

#### Scenario: 查看已识别访问
- **WHEN** 管理员打开访问明细
- **THEN** 每条记录展示完整必需字段，不显示原始客户端 IP 或完整原始日志

#### Scenario: 查看非成功响应
- **WHEN** 可识别爬虫收到 301、403、404 或其他有效 HTTP 状态码
- **THEN** 明细保存并显示实际状态，不把这些请求隐去或展示为成功抓取内容

### Requirement: 日期与爬虫筛选

系统 SHALL 支持按日期范围及爬虫身份组合筛选，日期边界与概览保持一致；无效日期范围须明确拒绝，不静默切换条件。

#### Scenario: 组合查询
- **WHEN** 管理员同时选择某日期范围和 Kimi-SearchBot
- **THEN** 结果只包含该时间范围内该爬虫的记录，并与概览对应口径一致

#### Scenario: 开始日期晚于结束日期
- **WHEN** 管理员提交颠倒的日期范围
- **THEN** 系统说明范围无效，不返回看似有效的替代查询结果

### Requirement: 稳定分页和空状态

系统 SHALL 提供有界分页，以访问时间及稳定次级顺序展示记录；空结果须同时显示采集状态，不得把断连、未安装或采集缺口解释为确定没有访问。

#### Scenario: 同时间多条请求
- **WHEN** 多条请求具有相同访问时间且管理员翻页
- **THEN** 分页保持确定顺序，不因相同时间随机重复或遗漏记录

#### Scenario: 筛选结果为空且采集异常
- **WHEN** 当前筛选没有记录而采集器已断连
- **THEN** 页面保留空结果并明确展示异常、最后心跳和最后数据时间

### Requirement: 核验依据可解释

系统 SHALL 允许管理员查看核验状态的含义、所用规则与证据更新时间，并将证据不可用、IP 不匹配及仅 UA 匹配明确区分。

#### Scenario: 查看未核验记录
- **WHEN** 管理员查看一条证据暂不可用的请求
- **THEN** 页面解释无法核验的原因，而不是将其显示为已确认平台访问或恶意请求
