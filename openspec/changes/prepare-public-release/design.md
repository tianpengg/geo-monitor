# Design

## Context

见 proposal.md。仓库尚无提交或远程地址；Git 凭据管理器存在多个账号，上传前须确认目标。现有下载白名单未含 LICENSE，镜像仅复制 README 和构建文件；前端素材已有 Inter / Tabler 许可。

## Goals / Non-Goals

Goals：首次提交具备可阅读说明与许可，许可随分发保留；公开内容脱敏，使用用户确认的 GitHub 账号。

Non-Goals：不修改采集或统计口径，不发布生产数据或旧部署 ZIP，不重写远程历史，不把首次公开当作完整容器验收。

## Decisions

- 根目录 LICENSE 使用用户选择的 MIT；pyproject / 前端元数据标记 MIT，镜像显式复制许可，采集器固定白名单增加许可。以包内容和 wheel 检查验证，不改变运行接口。
- 首页按使用场景、功能、部署、采集、限制、开发和文档组织；通用 1Panel 说明替换私人部署文档。原私人说明复制到忽略目录保留，公开历史仅泛化真实地址及现场细节，不改写历史测试结果。
- 保留第三方字体、图标许可，列出来源；社区模板禁止提交凭据和原始日志。GitHub 默认使用公开 geo-monitor 名称，账号必须由用户确认；已有非空同名仓库须先读取，不覆盖历史。
- 只通过 Git / GitHub 的正常认证流程使用现有凭据，不读取浏览器会话或密码；提交采用 GitHub 提供的 noreply 邮箱，避免公开本机私人邮箱。

## Risks / Trade-offs

- 认证账号不明确或授权不足 → 完成全部本地准备，缺失的账号 / 登录信息由用户提供，不猜测或索取明文令牌。
- 声称已完成生产验收 → 记录用户反馈的基础接入，完整故障 / 资源和双协议测试保持原待验状态。
- 个人服务器信息进入首次提交 → 检查当前索引与发布文件，使用示例地址，不推送本地运行文件。

## Migration Plan

本次不改数据库或生产部署。核对许可和源码包、运行相关回归后建立首次提交并公开推送；其他开发沿用原目录和锁定依赖。实际 GitHub 结果及 CI 状态记录在发布检查文档。
