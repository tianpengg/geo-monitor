# self-hosted-deployment Specification

## Purpose

让管理员可以使用 Docker 在自有 Linux 环境部署控制台和官网采集器，并在停止、重建容器后保留身份、记录和读取状态。该能力将部署条件、日志挂载、凭据配置与故障恢复说明纳入可验证交付，减少一次安装后的维护不确定性。

## Requirements

### Requirement: 控制台与采集器部署

项目 SHALL 提供 Docker Compose、镜像构建定义和配置示例，支持控制台与采集器同机或分机部署；分机时采集器主动连接后台，不要求向外暴露采集器服务端口。

#### Scenario: 在 Linux 部署控制台
- **WHEN** 管理员按配置示例准备环境并启动 Compose
- **THEN** 控制台可通过说明中的入口访问，启动错误能够被定位且不创建无关官网配置

#### Scenario: 在宝塔官网服务器部署采集器
- **WHEN** 管理员指定本站日志目录、日志文件和有效后台配置
- **THEN** 采集器可运行预检并启用采集，不要求修改网站业务代码

### Requirement: 日志只读挂载与持久化状态

部署 SHALL 以只读方式挂载所需日志目录，以可写持久化卷保存采集状态，并为控制台数据库提供独立持久化卷；日志轮转后的允许范围内文件须仍可访问。

#### Scenario: 容器重建
- **WHEN** 控制台或采集器容器被停止并使用原数据卷重建
- **THEN** 官网标识、访问记录和读取状态保留，未确认日志按规范恢复，不重复计数

#### Scenario: 日志发生文件替换
- **WHEN** Nginx 在已挂载目录内完成重命名与新建文件轮转
- **THEN** 采集器能够看到旧文件和新文件，不因仅绑定旧文件而失去后续日志

### Requirement: 配置与凭据保护

部署说明 SHALL 区分管理员登录凭据与采集凭据，给出受限权限的配置方式，支持管理员选择 HTTP 或 HTTPS；HTTP 须明确密码、会话、采集凭据及上报数据未经传输加密，HTTPS 须验证证书。示例不得包含可用的默认生产密码或真实凭据。

#### Scenario: 准备生产配置
- **WHEN** 管理员按照示例配置控制台和采集器
- **THEN** 说明要求设置管理员初始凭据、保护采集配置并配置与所选协议一致的上报地址和 Cookie

### Requirement: 安装、停止与重连说明

项目 SHALL 提供安装、预检、停止、重连、备份和恢复说明，明确停止不删除数据卷；复用原状态为续传，主动删除状态并重新初始化为建立新的采集基线。

#### Scenario: 暂停后恢复
- **WHEN** 管理员按说明停止采集器，随后使用原状态重连
- **THEN** 采集器恢复原来源，补采仍被保留的未确认数据，并报告无法恢复的缺口

#### Scenario: 查看运行边界
- **WHEN** 管理员阅读部署及故障恢复说明
- **THEN** 文档明确要求本站独立日志、可信客户端地址和足够源日志保留期限，说明源站流量覆盖及 copytruncate 的限制

### Requirement: 可复现的首版验收

项目 SHALL 提供可复现的验收步骤，验证真实新增日志、规则分类与核验、断网恢复、进程重启、响应丢失重传、日志轮转、正常无匹配和断连异常。

容量验证 SHALL 先按用户确认的合成测试基线记录数据规模、环境、批量处理及 30 天查询结果；真实官网峰值、平均日志行大小、轮转及未压缩保留窗口在生产部署前补充并复验。

#### Scenario: 执行部署验收
- **WHEN** 在受支持的 Linux / Docker 环境按验收步骤执行
- **THEN** 能以可检查的输入和后台结果确认各项标准，使用受控官方证据样本验证核验逻辑，不依赖外部真实爬虫即时访问

#### Scenario: 生产参数后补时执行测试基线
- **WHEN** 用户确认先使用测试基线，真实官网参数暂未提供
- **THEN** 验收记录列明合成输入、测量结果及测试环境边界，生产负载和保留窗口列为部署前补充项，不把合成结果解释为生产吞吐或补采时长承诺

### Requirement: 统一运维入口与本地产物
项目 SHALL 集中提供部署配置与运维脚本，文档、容器构建、采集器下载包及验收命令引用相同的有效入口。本地运行数据、打包及验收输出与源码分开；整理现有目录时保留数据及验收记录。默认本地存储路径调整后，显式数据库配置继续优先，已有旧默认数据库在新路径不存在时仍可被使用，生产持久化卷位置保持兼容。

#### Scenario: 从整理后的源码部署
- **WHEN** 管理员执行更新说明中的部署或采集器安装、停止及重连命令
- **THEN** 所有配置、构建上下文和包内脚本可找到，原有预检、只读挂载与持久化行为保持有效

#### Scenario: 已有本地数据库
- **WHEN** 启动时显式指定数据库，或旧默认数据库存在而新默认数据库不存在
- **THEN** 服务使用指定或已有数据库，不因目录调整静默创建空库；本次工作区迁移通过完整性校验保留已有文件

### Requirement: 一条命令部署控制台

项目 SHALL 提供 Linux Shell 部署入口，从完整源码检查 Docker 与 Compose，收集或读取后台地址、管理员凭据和端口，生成受限权限配置并启动控制台。新配置接受 HTTP / HTTPS：HTTP 默认开放直连端口并关闭 Secure Cookie，HTTPS 使用 Secure Cookie 和本机端口绑定；密码不得进入命令行参数或终端输出。既有配置不得被静默覆盖，重复部署保持原数据卷；仅在健康检查通过后报告成功，失败返回非零状态。

#### Scenario: 首次部署
- **WHEN** 管理员提供有效地址、端口及管理员凭据并执行入口
- **THEN** 入口以受限权限创建配置，特殊字符密码原样传入容器，健康通过后给出对应协议的接入说明

#### Scenario: 重复执行与失败
- **WHEN** 已有配置时重复执行，或 Docker、配置、构建、健康检查失败
- **THEN** 入口不删除或覆盖原配置和数据卷，重复部署复用配置，失败返回非零状态并提供不含密码的诊断方向

#### Scenario: 采集器入口
- **WHEN** 管理员选择采集器模式并提供后台地址和网站、来源标识
- **THEN** 入口调用支持 HTTP / HTTPS 的安装流程，日志路径及采集凭据按原流程输入，不自动修改网站证书、代理或日志

#### Scenario: HTTP 直连与登录
- **WHEN** 管理员指定 HTTP 服务器地址部署并访问开放的端口
- **THEN** 无需证书或反向代理即可登录并持续访问受保护接口，输出明文传输提示和端口放行说明

#### Scenario: HTTPS 可选与配置切换
- **WHEN** 管理员选择 HTTPS 或手动将既有配置切换协议后重新执行
- **THEN** HTTPS 仍要求有效证书且登录 Cookie 使用 Secure，地址与 Cookie 不一致的配置明确失败而不静默改写，原身份和数据保留

### Requirement: 公开交付与许可保留

公开源码、Python 包、生产镜像及采集器下载包 SHALL 保留项目 Apache-2.0 许可文本；已随项目分发的第三方素材 SHALL 保留各自许可及归属说明。公开说明 SHALL 使用示例地址和路径，不包含实际凭据、数据库、采集状态或服务器明细，并准确说明配置条件、来源核验和已执行验证的边界。

#### Scenario: 获取采集器或构建发行包
- **WHEN** 管理员下载采集器源码包或从公开源码构建 Python 包和镜像
- **THEN** 分发内容包含项目许可文本，采集器包仍只包含允许的常规文件，不加入真实配置或运行数据

#### Scenario: 首次公开仓库
- **WHEN** 维护者发布源码及项目说明
- **THEN** 首次提交排除实际配置、环境、数据库和状态，提供可用的部署 / 贡献 / 安全反馈说明，演示数据与测试结果不冒充生产结果

### Requirement: 采集器独立资源边界

采集器 Compose SHALL 默认配置 0.25 CPU、128 MiB 内存、64 个进程上限及 json-file 输出日志轮转（每文件 5 MiB、最多 2 个），CPU 和内存可通过明确的环境变量调整；根文件系统只读，状态卷独立可写。不得增加公开端口、host 网络、特权模式或 Docker socket 挂载，不修改官网文件、业务配置及 Nginx。文档须区分资源限制配置和 Linux 实际执行结果，说明构建安装与运行均有资源开销、补采受源日志保留和节流影响，生产需按真实流量验证。

#### Scenario: 同机运行边界
- **WHEN** 管理员按默认 Compose 启动采集器
- **THEN** 引擎对采集器应用资源和日志上限，源日志只读且状态可持久化，采集器停止或失败不会停止官网服务

#### Scenario: 配置与真实环境未验收
- **WHEN** 管理员调整资源参数或当前环境无法运行 Docker
- **THEN** 配置可明确核对，不能把配置解析或合成回归当作实际限额生效、生产吞吐或零影响证明
